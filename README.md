## Описание

Программа строит граф зависимостей Java-пакета из Maven-репозитория.
Все семь настроек читаются из XML. POM загружается по HTTP(S) и разбирается
самостоятельно средствами Python. Maven и библиотеки получения зависимостей
не используются. JAR-файлы не загружаются.

Этап 1: проверка настроек и вывод `ключ=значение`.
Этап 2: получение POM указанной версии и вывод прямых зависимостей.
Этап 3: рекурсивный DFS, транзитивные зависимости, циклы и фильтр.
Этап 4: прямые и транзитивные обратные зависимости.
Файл SVG и ASCII-дерево относятся к этапу 5.

## Запуск, сборка и тесты

Нужен Python 3.10 или новее, только стандартная библиотека.
Java, Maven и установка Python-пакетов не требуются.
Команды из корня проекта:

```sh
python3 -B src/main.py examples/junit.xml
sh run.sh examples/slf4j.xml
sh run.sh examples/test.xml
sh run.sh examples/graph-cycles.xml
sh run.sh examples/reverse.xml --reverse
make build
make test
make demo-errors
```

`make build` проверяет импорт исходников без создания файлов сборки.
Без make: `PYTHONPATH=src python3 -B -m unittest discover -s tests -v`.
Демонстрация ошибок: `PYTHONPATH=src python3 -B examples/demo_errors.py`.
В PyCharm скрипт запуска - `src/main.py`, рабочий каталог - корень проекта.
Для этапа 3 передайте `examples/graph-cycles.xml`, для этапа 4 передайте
`examples/reverse.xml --reverse`. Оба примера работают без интернета.

## Настройки XML

Корень документа - `<config>`. Все семь элементов обязательны.
Пример целиком находится в `examples/junit.xml`.

| Элемент | Назначение и допустимое значение |
| --- | --- |
| package | Maven-координаты `groupId:artifactId`, например `junit:junit` |
| repository | Базовый HTTP(S) URL Maven или путь к JSON в тестовом режиме |
| test_mode | Строго `true` или `false`; в тесте package состоит из букв A-Z |
| version | Точная версия, например `4.13.2`, без слешей и пробелов |
| output | Будущий файл `.svg`; родительский каталог должен существовать |
| ascii_tree | `true` или `false`; настройка дерева для этапа 5 |
| filter | Подстрока исключения для этапа 3; пустой элемент отключает фильтр |

Пути считаются от каталога XML. Неизвестные, повторные и вложенные поля
отклоняются. Ошибка любого параметра даёт сообщение в stderr и код 2.
Успешный запуск возвращает 0. На этапах 3 и 4 filter применяется к именам
пакетов с учётом регистра. output и ascii_tree пока только проверяются.

## Этап 3. Обход графа

Запуск без дополнительных флагов строит граф из указанного пакета.
При посещении узла программа запоминает его соседей и рекурсивно обходит
их в порядке объявления. Общий узел читается один раз. Ребро к узлу
в активной цепочке отмечается как цикл и остаётся в графе.
Фильтр исключает совпавшие пакеты и пути, которые проходят через них.
В Maven имя для фильтра имеет вид `groupId:artifactId`, без версии.
Узел Maven определяется именем и версией.

```sh
sh run.sh examples/test.xml
sh run.sh examples/graph-cycles.xml
sh run.sh examples/junit.xml
sh run.sh examples/junit.xml --direct
```

В первом примере A зависит от B и C, а B зависит от D. DFS посещает
A, B, D, C. Во втором примере C тоже зависит от D, а D зависит от B.
Программа показывает ребро D → B как цикл. Фильтр X убирает BX,
поэтому из A также недостижим Z. Изолированный F не входит в граф A.
В этом JSON G ссылается на себя: достаточно поставить G в поле package,
чтобы увидеть цикл G → G.

В Maven-граф входят обязательные зависимости compile и runtime.
Команда с `--direct` сохраняет вывод этапа 2 со всеми прямыми объявлениями
POM. Для JUnit 4.13.2 она показывает hamcrest-core 1.3 (compile)
и hamcrest-library 1.3 (test). В графе остаётся hamcrest-core.

## Этап 4. Обратные зависимости

Флаг `--reverse` разворачивает рёбра графа и запускает DFS от выбранного
пакета. В результат входят все пакеты, у которых есть путь к нему.
Исходный пакет пропускается даже при наличии цикла. В тестовом режиме
поиск идёт по всему JSON-репозиторию. Фильтр применяется при обходе.

```sh
sh run.sh examples/reverse.xml --reverse
sh run.sh examples/isolated.xml --reverse
sh run.sh examples/reverse-maven.xml --reverse --catalog examples/maven-catalog.json
```

Для D выводятся B и C (прямые), A и E (через другие пакеты). Цикл B и D
не зацикливает обход. Если заменить фильтр X на A, останутся B и C,
потому что путь от E проходит через A. Для изолированного F выводится
`(нет)`. Поиск для G с петлёй также возвращает пустой список.

Для Maven укажите `--catalog`, путь к JSON-массиву координат в формате
`groupId:artifactId:version`. POM не содержит списка использующих его
пакетов, поэтому поиск ограничен записями каталога и их зависимостями.
В приведённом примере JUnit 4.13.2 зависит от hamcrest-core 1.3.
В POM SLF4J API JUnit относится к тестам, поэтому в этом результате
SLF4J API отсутствует.

## Как разбирается Maven

Из `groupId:artifactId:version` строится URL вида
`group/id/artifactId/version/artifactId-version.pom`.
Поддержаны XML namespace POM, свойства `${...}`, parent POM,
dependencyManagement и импорт BOM. Parent и BOM загружаются из того же
репозитория. Повторные запросы кешируются в памяти. Циклы parent/BOM,
отсутствующие версии, неизвестные свойства, HTTP 404 и ошибки XML
сообщаются пользователю. Ограничения: 15 секунд на запрос, POM до 4 МиБ.

Читаются непосредственные dependencies проекта с наследованием от parent.
Секции плагинов и dependencyManagement сами по себе в результат не входят.
Зависимости из Maven-профилей не активируются. Это учебный разбор POM,
а не полная реализация effective POM: переопределение ребёнком свойств
уже разрешённых зависимостей родителя не поддерживается.
Версия выбирается точно; диапазоны, LATEST и поиск timestamped SNAPSHOT
по maven-metadata.xml не реализованы. Дополнительные repositories из POM
и локальный relativePath родителя не используются.

## Исходники и функции

- `src/config.py`: Config - настройки; parse_bool - флаги;
  check_package и check_repository - координаты и URL; collect_fields -
  структура XML; read_fields - чтение; check_values - проверка полей;
  load_config - разрешение путей; display_config - вывод этапа 1.
- `src/main.py`: main разбирает аргументы, show_dependencies печатает
  прямые объявления, show_graph выводит граф и циклы, show_reverse печатает
  обратные зависимости, run_mode выбирает режим запуска.
- `src/graph.py`: Graph хранит рёбра, walk рекурсивно посещает узлы,
  build_graph запускает обход, reverse_edges разворачивает рёбра,
  reverse_dependents ищет пакеты с помощью того же DFS.
- `src/analysis.py`: forward_graph выбирает источник, maven_neighbours
  возвращает соседей Maven, matches проверяет фильтр, load_catalog читает
  каталог Maven, reverse_packages выбирает источник обратного поиска.
- `src/pom.py`: expand - свойства; parse_pom - XML; text - текст поля;
  own_properties - свойства проекта; Dependency.key и display - идентификатор
  и вывод зависимости; Model - данные POM; dependency - разбор объявления;
  project_properties - объединение свойств и координат проекта.
- `src/maven.py`: pom_url - адрес POM; download - HTTP-загрузка;
  Repository.__init__ - репозиторий и кеш; parent_model - родитель;
  managed_dependencies - управляемые версии; model - сбор данных POM;
  direct_dependencies - список прямых зависимостей.
- `src/test_repository.py`: check_graph - проверка JSON-графа;
  load_test_graph читает граф, require_package проверяет наличие пакета,
  direct_test_dependencies возвращает его непосредственных соседей.
- `examples/demo_errors.py`: main - семь примеров неверных параметров.
